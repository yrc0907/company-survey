# 开放知识平台前端与动效规范

> 状态：目标设计规范，尚未实现。视觉方向采用 shadcn/ui 的克制、清晰和一致性，但不把默认组件样式原样拼成模板页面。

## 1. 设计方向

- 第一屏就是公开知识列表，不做营销 Hero；
- 浅色中性界面，正文和来源优先，避免黑色大框、渐变和装饰性背景；
- 使用一种低饱和强调色表达选中、链接、主要操作和可信状态；
- 列表使用分隔线和留白，不把每条内容包成厚重卡片；
- 左侧文件树、中间正文、右侧 AI 形成稳定工作区；
- 正文署名采用页边批注，默认安静，悬停或“贡献追踪”模式才展开；
- 高风险操作始终显示目标分支、Diff、权限和不可逆后果。

推荐基础技术：Tailwind CSS + shadcn/ui + Radix UI + Lucide。V1 动效优先使用 CSS transition、Radix `data-state` 和 `tw-animate-css`；不为普通弹窗和列表引入 GSAP。只有出现跨容器共享布局或复杂编排的真实需求时，再单独评估 `motion/react`。

## 2. 页面结构

### 2.1 公开首页

```text
┌ Logo ───── 搜索项目、报告、公司、结论 ─── 探索  提交研究  登录 ┐
├─────────────────────────────────────────────────────────────┤
│ 推荐  最新发布  最近更新  待完善  争议内容                    │
├──────────────┬───────────────────────────┬──────────────────┤
│ 分类与筛选    │ 公开研究列表               │ 热门主题          │
│ 企业          │ 头像 用户名 · 更新时间      │ 活跃贡献者        │
│ 行业          │ 报告标题                   │ 最近合并          │
│ 政策          │ 两行摘要                   │ 待解决问题        │
│ 技术          │ 来源 32 · 贡献者 8 · MR 3 │                  │
└──────────────┴───────────────────────────┴──────────────────┘
```

- 顶栏 56px，搜索是第一视觉入口；
- 左侧筛选 220-240px，中间列表最小 640px，右侧信息 260-300px；
- 每条报告是 96-132px 的列表行，展示作者、标题、两行摘要、分类、来源数、贡献者和待审核数；
- 搜索支持项目、文件、结论、来源和用户，并保留筛选条件在 URL 中；
- 小屏移除右栏，筛选进入 Sheet，列表仍是第一屏。

### 2.2 项目详情

```text
┌ 用户/项目名   公开 · main@v42      关注  创建草稿  提交修改    ┐
│ 内容     修改申请  问题  历史  贡献者                         │
├────────────┬────────────────────────────┬────────────────────┤
│ 文件搜索    │ 报告正文                    │ AI 助手             │
│ main ▼     │                            │ 问答 / 补来源       │
│ ▾ 报告      │ 市场分析                    │ 生成 Patch          │
│   概览      │ 正文……                     │ 审查事实             │
│   市场      │                            │                     │
│ ▾ 来源      │ 张三贡献 · MR #28           │                     │
│ ▾ 数据      │ 查看历史 / 引用 / Diff       │                     │
└────────────┴────────────────────────────┴────────────────────┘
```

- 左栏默认 260px、右栏默认 340px，支持拖动与收起；
- 正文阅读列保持约 680-820px，不让超宽屏形成难读长行；
- 顶部项目操作条保持紧凑，不使用大面积品牌头图；
- 章节左侧显示证据状态和贡献标记，悬停打开 HoverCard；
- “贡献追踪”开启后逐段显示作者、Commit、MR、审核者和时间。

### 2.3 草稿编辑

- 顶部固定显示 `main@v42 -> 我的草稿`、自动保存状态和已修改文件数；
- 文件树用小圆点表示修改，不通过红绿大色块制造噪音；
- TipTap 支持 Markdown 快捷输入、标题、表格、引用、脚注和来源块；
- AI 建议以 Patch 卡片显示“加入草稿 / 忽略 / 查看依据”，没有直接发布按钮；
- 游客草稿显示本地保存提示，只有“提交审核”触发登录；
- base revision 过期时先展示冲突，不允许静默覆盖。

### 2.4 合并申请

页面顶部展示标题、提交者、目标分支、状态和自动检查；主体提供：

```text
讨论 | 修改内容 | 来源检查 | 提交记录

原文                    修改后
旧结论                  新结论
                        + 新增引用 [3]

引用完整 3/3  · 失效链接 0 · AI 辅助 是 · 冲突 1
```

- 支持 inline 和 split Diff；窄屏只用 inline；
- 评论锚定到稳定 Block ID，而不是脆弱行号；
- `要求修改`、`批准`、`合并`使用不同语义层级；只有维护者看见合并按钮；
- 合并前确认弹窗明确列出目标分支、Commit 数、未解决评论和贡献署名。

### 2.5 用户、收件箱与管理

- 用户主页展示头像、简介、领域、公开项目、被合并贡献、审核记录和时间线；
- 不在 V1 上线按字数或点赞计算的排行榜；
- 收件箱按“待我审核 / 我的提交 / 评论 / 系统”分组；
- 管理后台采用紧凑表格处理举报、侵权、封禁和下架，不复制普通内容页布局。

## 3. shadcn/ui 组件映射

| 场景 | 组件 |
| --- | --- |
| 全站搜索 | `Command`、`Popover`、`Input` |
| 登录注册 | `Form`、`Input`、`Button`、`Alert` |
| 用户与贡献者 | `Avatar`、`HoverCard`、`Tooltip` |
| 项目导航 | `Tabs`、`Breadcrumb`、`DropdownMenu` |
| 文件树 | `Collapsible`、`ContextMenu`、`ScrollArea` |
| 三栏工作区 | `ResizablePanelGroup`、`Separator` |
| 游客登录迁移 | `Dialog`、`AlertDialog` |
| 移动端侧栏 | `Sheet`、`Drawer` |
| 通知与保存状态 | `Sonner`、内联状态文本 |
| 加载与 AI 流式输出 | `Skeleton`、`Progress` |
| 设置与权限 | `Select`、`Checkbox`、`Switch` |

组件源码进入仓库后统一封装，不允许页面自行复制一套 Button、Dialog、Toast 或权限提示。

## 4. 视觉变量

```text
背景：白色 / 极浅中性灰
正文：接近黑色的中性前景
次级文字：中性灰
强调色：低饱和深绿或最终品牌色
成功：绿
警告：琥珀
危险：红
信息：只在确有语义时使用蓝色
圆角：控件 6px，列表/面板 8px，弹窗 12px
间距：4px 基础网格
```

状态不能只依赖颜色。事实、推断、争议、过期和冲突同时使用文字、图标和颜色。

## 5. 动效原则

动效只用于解释状态、层级和空间变化。高频输入、正文编辑、滚动、表格浏览和普通列表切换以即时响应为主。

| 交互 | 进入 | 退出 | 表现 |
| --- | --- | --- | --- |
| 按钮/列表 hover | 100-140ms | 80-110ms | 背景、文字或边框对比变化 |
| Tooltip / Dropdown | 150-180ms | 110-140ms | opacity + 2-4px 位移 |
| 文件夹展开 | 160-200ms | 120-150ms | 高度/opacity；保持树节点位置稳定 |
| Dialog / Popover | 200-240ms | 150-180ms | opacity + scale `0.98 -> 1` |
| Sheet / AI 侧栏 | 240-300ms | 180-220ms | 与来源方向一致的位移 |
| 页面内容切换 | 160-220ms | 120-160ms | 轻微 cross-fade，不做全屏滑动 |
| Diff 新增/删除 | 220-300ms | 无循环 | 背景高亮短暂增强后稳定 |
| 草稿保存完成 | 120-180ms | 100ms | 图标/文字状态切换，不弹 Toast |
| 合并成功 | 280-360ms | 200ms | 状态条与贡献记录更新，不用彩带 |

默认缓动使用 `cubic-bezier(0.22, 1, 0.36, 1)`；退出约为进入时长的 75%。禁止 `transition: all`、弹跳、无限脉冲、滚动视差和为了“高级感”添加的装饰性动画。

### AI 动效

- 请求开始后立即显示当前阶段：检索、重排、生成；
- 文本按流式响应自然增长，不使用逐字机打动画拖慢真实输出；
- 工具步骤只在发生时展开，完成后折叠为可审计摘要；
- 引用到达时在对应回答末尾淡入，不让内容跳位；
- 失败保留用户问题和已取得证据，提供明确重试，不清空对话。

### Reduced Motion

`prefers-reduced-motion: reduce` 下：取消位移、缩放、骨架 shimmer 和自动滚动，只保留必要的即时 opacity/颜色状态。键盘焦点环永远不能被动画隐藏。

## 6. 响应式

| 宽度 | 布局 |
| --- | --- |
| `>= 1280px` | 三栏项目工作区，左右栏可调整 |
| `960-1279px` | 文件树保持，AI 变为可呼出的 Sheet |
| `< 960px` | 正文优先，文件树 Drawer，AI 底部 Drawer |
| `< 640px` | 首页单列列表，筛选 Sheet，Diff 使用 inline |

移动端不缩小桌面三栏。所有图标按钮至少 40px 可点击区域，主要提交按钮至少 44px 高。

## 7. 必须覆盖的状态

- 首次使用、空项目、空文件夹；
- 加载、部分加载、流式 AI；
- 离线和自动保存失败；
- 游客草稿待登录迁移；
- 无权限、项目锁定、内容下架；
- base revision 过期和合并冲突；
- 来源失效、引用缺失和事实争议；
- AI 限额、Provider 超时和确定性降级；
- 审核中、要求修改、批准、拒绝、已合并和已关闭。

## 8. 前端验收标准

- 首页首次视口直接显示真实公开项目列表和搜索；
- 项目页可在不登录时阅读、搜索和限额问 AI；
- 游客编辑后刷新页面草稿仍存在，登录后能无损迁移；
- AI 生成修改只进入草稿，不能直接改变公开正文；
- 合并申请可逐段查看 Diff、引用和贡献归属；
- 合并后正文、历史和用户贡献页署名一致；
- 桌面、平板和手机均无重叠、横向溢出或不可达操作；
- 键盘可完成搜索、编辑、提交和审核；
- Reduced Motion、焦点、对比度和错误恢复均通过自动化与人工验收。

# 北京新橙科技（iCourt）2026 独立研究

更新时间：2026-09-03  
研究对象：北京新橙科技有限公司（品牌：iCourt）  
研究状态：公开资料研究；非上市主体的收入、利润、客户合同和续费率不作无来源推断

## 一、先给结论

iCourt 不是单一法律检索工具，而是把法律数据库、案件办理、律所管理、课程和 AI 助理组合成法律人的工作平台。2026 年官网首页重点展示 Alpha、AlphaGPT、AlphaClaw、AlphaNote 和 Skill 商店，说明公司正在从“数据库 + 软件”转向“法律工作流 + Agent + 专业知识资产”。

我的判断是：iCourt 的真正壁垒取决于三件事：法律数据的权威性和持续更新、律师业务流程中的实际使用深度、以及 AI 输出能否通过法规/案例引用和人工复核形成可交付成果。官网宣传的用户数、数据量和提效指标只能说明企业定位，不能替代审计收入、续费率或第三方准确率。

## 二、研究方法与证据分层

- **fact（事实）**：官网结构化元数据、产品页明确功能、工商/监管/公开公告可直接定位的内容。
- **company_claim（企业自述）**：官网“30 万法律人”“2 万律所”“6 亿+数据”“3 秒响应”等宣传数字。
- **inference（推断）**：根据产品组合、交付流程、数据闭环推导的商业含义。
- **needs_verification（待核验）**：收入、利润、客户合同、价格、续费、ROI、模型准确率、数据授权范围和岗位真实职责。

官网允许爬虫访问并提供 sitemap，但部分内容由 JavaScript 渲染；本报告保存页面 URL、抓取日期和证据边界，不把页面快照当审计材料。

## 三、企业主体与发展阶段

iCourt 官网 HTML 的 `Organization` 结构化数据明确 `legalName=北京新橙科技有限公司`，品牌名为 iCourt，主营法律科技与司法信息化。关于页元数据称公司 2013 年成立，研发执业思维课程、律所管理方案和法律科技产品；截至 2024 年 6 月，官网自述超过 30 万名法律人、1.5 万家律所使用产品。

上述成立时间和用户数字属于官网口径；注册资本、股权、实际控制人、历次融资和财务报表需通过国家企业信用公示或企业尽调报告补齐。

## 四、产品矩阵

### Alpha 法律智能操作系统

官方产品页将 Alpha 定义为法律大数据检索、案件协作、律所管理和线上课程的一体化系统，覆盖网页版、客户端、Word 插件、iOS、Android、iPad 和小程序。

### AlphaGPT

覆盖法律咨询、合同审查、类案检索、法律意见、文书起草和法律阅卷。官网称其融合自研法律垂类大模型与 DeepSeek 推理能力，并支持 PPT、思维导图、万字法律意见书等输出。

### AlphaClaw 与 Skill 商店

首页将 AlphaClaw 定位为法律 AI 数字员工，强调调用工具、复用经验、持续记忆和 Skill 组合。Skill 商店包含官方研发、校友共创和精选能力。是否形成独立订阅、是否支持租户隔离和审计日志仍待核验。

### AlphaNote

官网将其描述为法律行业 AI 硬件，主张从录音、案情研讨到最终交付打通流程。硬件型号、出货量、价格和隐私策略尚未公开充分。

## 五、法律数据能力

Alpha 产品页自述拥有 1.5 亿+裁判文书、300 万+法律法规；律所管理页自述 6 亿+法律大数据库；AlphaGPT 页面又出现 1.8 亿篇裁判文书和 8 大参照级别。不同页面数字不一致，可能来自更新时间、数据对象或统计口径差异。

**怎么核验：** 固定统计日期，区分裁判文书、法规、司法观点、专题库和版权数据，逐项确认来源、授权、更新频率、去重规则和可导出范围。**优点：** 数据规模和专业语料有机会提高检索粘性。**缺点：** 版权、更新、错误纠正和数据安全成本高。**失败条件：** 直接用最大宣传数字证明数据壁垒。

## 六、案件办理方案

iCourt 案件办理方案包括智能检索、标准化案件管理、智能证据阅卷和 Alpha Box。官网描述案件以项目制建立，支持任务、文档、证据清单、目录和时序图，并支持语音、图片转文字。

**怎么做：** 用“案情输入 → 检索 → 证据整理 → 法律分析 → 文书交付 → 客户报告”定义验收；记录人工节省时间、引用准确率、遗漏率和交付返工。**为什么：** 只有进入完整工作流，AI 才不是独立聊天窗口。**优点：** 能沉淀案件模板和团队经验。**缺点：** 法律责任高，错误输出必须人工复核。**失败条件：** 只测生成速度，不测引用、证据完整性和责任留痕。

## 七、律所管理方案

律所管理页按大数据开放平台、项目管理、团队协同、律所 OA 和客户服务五部分组织产品。官网自述 18 大领域、120+ 标准化项目模板、近 20 种客户服务报告，并支持并发账号、API 接入和本地化部署。

**怎么做：** 将模板启动时间、任务按时率、文档归档率、客户报告生成时间和续约/转介绍变化作为指标。**为什么：** 管理软件的价值应体现为组织流程和客户服务结果，而不是菜单数量。**优点：** 迁移成本和知识复用可能形成粘性。**缺点：** 实施与培训重，律所差异会带来定制。**失败条件：** 每家律所都做一套二开，无法形成模板复用。

## 八、AlphaGPT 能力验证

官网公开的六类能力是法律咨询、合同审查、类案检索、法律意见、文书起草和法律阅卷。页面宣称“3 秒应答”“3 分钟生成意见书”“一键验证法规与类案匹配”。这些都是 company_claim。

**怎么做：** 建立包含法规适用、类案召回、合同风险、长卷宗、跨文档引用和拒答边界的 Golden Set；测召回率、引用正确率、幻觉率、延迟、成本和人工采纳率。**为什么：** 法律 AI 的可交付性由正确引用和可审查链路决定。**优点：** 指标可复现、便于版本比较。**缺点：** 标注成本高，法律结论需要专业人员。**失败条件：** 把模型供应商名称或演示案例当作准确率证明。

## 九、AlphaClaw 数字员工路径

**怎么做：** 先限定低风险、可回滚的任务，例如资料归档、检索报告草稿、案件时间线和模板填充；工具调用必须经过权限、预算和人工确认，记录每一步输入、来源、动作和结果。

**为什么：** Agent 比问答更接近法律人的真实工作，但也更容易越权、误用和泄露案件信息。**优点：** 有机会提高复杂任务的交付效率和复用能力。**缺点：** 权限、审计、隐私和责任成本显著增加。**失败条件：** 让 Agent 自动发送法律意见、修改正式文书或访问无授权案件。

## 十、客户与场景

目标用户包括律师个人、律所团队、企业法务和司法相关机构；场景包括诉讼、非诉、合同、法律检索、证据整理、客户报告、律所财务人事和知识管理。

官网公开的“30 万法律人、2 万律所”等数字属于企业自述，不等于付费客户数。**怎么做：** 对中粮、来伊份、百威等官网案例或公开客户线索逐项寻找合同、验收、续费和真实指标。**优点：** 能判断产品是否进入核心流程。**缺点：** 法律客户通常不会公开采购价格和案件效果。**失败条件：** 用案例 Logo 或用户累计数替代留存和收入。

## 十一、商业模式与价格

可能的收入组合包括个人/团队订阅、律所管理系统授权、数据库账号/API、私有化部署、培训课程、实施服务、硬件和 Agent/Skill 增值服务。官网未提供统一公开价，部分页面以免费试用、预约演示和直接购买并列呈现。

**怎么做：** 为每个产品记录账号数、数据权限、订阅周期、并发、API、部署、培训、维保和升级费用；将一次性收入与经常性收入拆开。**为什么：** 只有知道续费和服务成本，才能判断平台化是否成立。**优点：** 便于设计分层产品。**缺点：** 价格透明度低，销售报价可能高度定制。**失败条件：** 把“免费试用”写成免费商业模式，或把官网优惠写成长期价格。

## 十二、数据安全与合规

Alpha 产品页自述通过 ISO 27001 和公安部信息系统三级等保认证，并提供权限控制、加密、离职账号数据清理和本地化部署选项。认证证书编号、有效期、适用系统范围和具体测评报告需要原件核验。

法律案件、合同和客户信息属于高敏感数据。**怎么做：** 建立租户隔离、最小权限、加密、脱敏、日志审计、数据留存/删除、模型训练禁用和事故响应流程。**优点：** 有助于进入大型律所和法务客户。**缺点：** 合规投入会提高交付和运营成本。**失败条件：** 把“通过认证”理解为所有客户数据使用方式都合规。

## 十三、竞争与替代方案

竞争对象应按场景拆分：法律数据库与检索可对比威科先行、北大法宝、无讼等；律所管理可对比通达海、法大大及通用 OA/低代码；通用 AI 办案可对比大模型厂商和律所自建知识库。

**怎么做：** 在同一法律问题集和同一团队规模下比较数据覆盖、引用质量、检索速度、模板、部署、权限、API、三年 TCO 和迁移成本。**为什么：** iCourt 的优势若存在，应来自专业数据和工作流，而不是单纯模型参数。**优点：** 能定位细分场景。**缺点：** 竞品价格、数据授权和效果很少公开。**失败条件：** 用产品功能数量做品牌排名。

## 十四、组织与 FDE/解决方案岗位

官网关于页和产品页能证明产品方向，但没有公开、稳定的 FDE 岗位 JD。若招聘中出现 FDE、实施顾问、解决方案或客户成功岗位，应确认它是否负责“客户案件/管理流程 → 标准模板 → 产品反馈 → 复盘续费”。

**正向做法：** 让 FDE 进入真实律所或法务场景，记录数据接入、模板配置、模型效果、权限风险、交付人天和复用率，并拥有产品评审入口。**优点：** 把律师经验变成可复制产品。**缺点：** 需要法律专业、产品和工程协作，前期驻场成本高。**失败条件：** 只有售前演示、投标和二开，没有产品化指标。

## 十五、政策与“十五五”映射

可映射的政策方向包括人工智能赋能、数据要素、数字政府、司法信息化、网络安全、知识产权和专业服务业数字化。正确链路是：

```text
政策原文 → 律所/法务的建设要求 → iCourt 产品能力 → 采购/验收 → 客户结果
```

政策只能证明需求方向，不能证明获得订单或补贴。尤其法律 AI 还要额外关注数据授权、模型安全、生成内容责任和专业人员最终审查。

## 十六、发展路径：怎么做、为什么、优劣势

### 路径 A：法律数据库 + 可验证检索

持续提升数据授权、更新、引用和可解释性，把检索报告做成律师可复核的证据链。优点是专业壁垒和粘性强；缺点是数据成本和版权风险高。

### 路径 B：案件工作流平台

把检索、证据、文书、客户报告和知识库串成一个项目闭环。优点是使用深度和迁移成本提高；缺点是实施复杂、需要改变团队习惯。

### 路径 C：受控法律 Agent

从低风险草稿和资料整理开始，通过工具权限、人工确认和审计逐步扩大任务范围。优点是 AI 价值更接近交付；缺点是责任和安全边界最复杂。

### 路径 D：律所数字化服务

用模板、培训、顾问和本地化部署服务大型律所。优点是客单价和长期关系可能更高；缺点是服务人力会侵蚀软件毛利，必须控制定制比例。

## 十七、三种经营情景

| 情景 | 触发证据 | 策略 | 优点 | 风险 |
| --- | --- | --- | --- | --- |
| 平台化成功 | 订阅/续费增长，AI 采纳率和模板复用率上升 | 深化数据库、工作流和受控 Agent | 收入稳定性和迁移成本增强 | 合规、算力和标注成本上升 |
| 高服务、低复用 | 客户增长但实施人天和二开占比高 | 收缩定制，优先模板和标准 API | 保住客户关系 | 交付成本吞噬毛利 |
| 数据/合规受限 | 授权、隐私或模型责任出现重大问题 | 强化本地化、脱敏、审计和人工复核 | 降低事故风险 | 产品迭代和商业化速度下降 |

## 十八、风险、反方证据与待核验

风险包括法律数据库授权与版权、生成式 AI 责任、案件隐私、模型幻觉、律所采购周期、交付定制、客户集中、数据更新、第三方模型依赖和硬件售后。

反方观点是：iCourt 的数据和行业经验可能很有价值，但高用户数不等于高付费率；AI 能力也可能提升展示效果，却未必降低律师交付成本。最终必须用续费、ARPU、人工采纳率、引用正确率、项目人天和客户验收反证或支持。

## 十九、Yu 的最终判断

iCourt 最合理的战略不是与通用大模型比“谁回答更像人”，而是用授权法律数据、案件工作流、团队模板和可审计 Agent 做出法律人的交付系统。Alpha 负责平台底座，AlphaGPT 负责垂直能力，AlphaClaw 负责复杂任务自动化；三者只有在权限、引用、人工审查和客户续费同时成立时，才会从产品组合变成商业壁垒。

目前公开资料足以确认 iCourt 正在向法律 AI 工作平台升级，但不足以确认收入规模、盈利能力、续费率、模型准确率和 Agent 的真实生产使用。对求职者而言，最值得选择的是能接触案件数据、产品反馈和效果指标的 FDE/解决方案岗位；只有演示、投标和驻场而没有产品化权力的岗位，长期成长有限。

# 个人调研工作台产品规格

> 版本：0.1
>
> 目标：以最少工程组件实现“资料可追溯、结论可核验、AI 改写可回滚”的个人研究闭环。

## 1. 用户与问题

唯一用户是部署者本人。典型研究对象包括企业、行业、竞品、政策和岗位机会。

现有痛点：

- 网页、PDF、图片、新闻和个人笔记分散，找回原始依据困难；
- 企业调研容易把官网宣传、公开事实和个人推断混在一起；
- 比较多家企业时，需要反复在报告、政策和来源之间切换；
- AI 可以辅助阅读和改写，但不能无依据写结论或直接覆盖报告；
- 部署在个人服务器后，需要保留资料、版本和引用，不能依赖聊天记录。

## 2. 产品原则

```text
来源优先于文笔
引用优先于结论
建议优先于自动修改
关系查询优先于模型猜测
最少基础设施优先于技术堆叠
```

## 3. 信息架构与前端布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 品牌 / 全局搜索 / 新建企业 / 新建报告 / 模型与搜索状态        │
├──────────────┬───────────────────────────────┬──────────────┤
│ 左侧：资料库  │ 中间：报告阅读与编辑            │ 右侧：AI 助手 │
│              │                               │              │
│ 企业          │ 标题、状态、可点击目录          │ 选中文字问答  │
│ 行业          │ Markdown 编辑/预览              │ RAG 引用结果  │
│ 政策          │ 引用、结论标记、版本 Diff        │ 改写建议 Diff │
│ 竞品          │                               │ 关系摘要      │
│ 来源与标签     │                               │              │
└──────────────┴───────────────────────────────┴──────────────┘
```

### 3.1 高优先级交互

1. 新建企业或行业对象，选择企业/行业/竞品/政策模板；
2. 导入 URL、PDF、图片或粘贴文本；
3. 查看来源解析出的段落、页码、抓取时间和哈希；
4. 搜索企业、报告、章节、来源或关键词，点击直达；
5. 选中正文后使用浮动工具栏执行“问 AI / 解释 / 补来源 / 改写”；
6. AI 在右侧返回答案、引用和 Diff；
7. 用户确认 Diff 后生成新版本，旧版本仍可回滚；
8. 选择多家企业生成对比表或查看关系图。

## 4. 功能范围

### 4.1 V1：可部署 MVP

| 功能 | 验收定义 |
| --- | --- |
| 单账号保护 | 未认证请求不能访问报告、来源、模型或搜索接口 |
| 企业与报告 CRUD | 能创建、编辑、归档企业和报告，不删除历史版本 |
| Markdown 报告 | 支持标题、可点击目录、引用、结论标记和全文预览 |
| 来源导入 | URL、PDF、图片、粘贴文本均生成来源记录和解析状态 |
| 多模态解析 | 文本 PDF 提取原生文字；扫描 PDF/图片可渲染页面后交给视觉模型 |
| 全文检索 | 搜索报告、章节、来源和标签，结果能跳转到具体段落 |
| 选区 AI 助手 | AI 读取选中段落及相邻上下文，返回带引用的回答或 Diff |
| RAG 问答 | 仅从当前工作区的来源片段检索，并显示引用 |
| 版本与导出 | 保存版本、查看 Diff、回滚、导出 Markdown/PDF |

### 4.2 V2：功能完整版

| 功能 | 验收定义 |
| --- | --- |
| 调研模板与问题清单 | 每份报告可维护待验证问题，AI 检索围绕问题与证据推进 |
| 结论可信度 | 支持 `fact`、`inference`、`needs_verification`、`conflict` 四种状态 |
| 来源快照与变化检测 | 保存正文快照/哈希；手动刷新时提示哪些引用和结论可能过期 |
| 企业横向比较 | 对比产品、客户、商业模式、价格公开度、竞品、政策契合度与风险 |
| GraphRAG-lite | 企业、产品、行业、竞品、政策章节、来源和结论可关系查询并呈现图谱 |
| 受控研究 Agent | 搜索多个来源、阅读、提取证据、生成草稿；每个写入步骤均等待确认 |

### 4.3 明确不做

- 团队协作、评论、公开分享链接和社交功能；
- 任意文件读取、任意 Shell、任意 SQL、任意网页自动化或绕过网站限制；
- 自动发布报告、自动发消息、自动购买任何第三方服务；
- 默认自部署大模型、Neo4j、Redis、RabbitMQ、Temporal、Kubernetes 或多 Agent；
- 在没有来源时让 AI 编造企业数据、价格、政策结论或竞争判断。

## 5. RAG 与 GraphRAG-lite

### 5.1 路由规则

```text
选中文字提问
  -> 选区 + 相邻段落
  -> 直接模型上下文，不调用全库 RAG

当前报告/来源问题
  -> PostgreSQL 全文检索或可选向量检索
  -> RAG + 引用片段

跨企业/产品/政策/竞品问题
  -> entity + relation_edge 关系查询
  -> GraphRAG-lite + 必要的 RAG 证据
```

### 5.2 关系模型

```text
企业 -> 产品 -> 行业 -> 竞品
  |        |        |       |
  +------> 来源 <----+----> 政策章节
                   |
                 结论
```

关系必须有来源和创建方式：`manual`、`model_candidate` 或 `confirmed`。模型只能提出关系候选；用户确认前不能作为最终报告事实。

### 5.3 事实边界

- 来源原文、PDF 页码、用户确认的结构化字段属于事实证据；
- AI 对事实的归纳属于解释；
- 价格、客户量、融资、市场份额、政策效果等未经独立来源验证的内容必须标注待核验或官网自述；
- 多来源描述同一事实不一致时标记 `conflict`，不让模型投票决定。

## 6. 数据模型

| 表/对象 | 关键字段 |
| --- | --- |
| `workspace` | 单用户工作区、创建时间、配置 |
| `company` | 名称、别名、行业、简介、标签、状态 |
| `report` | 企业/行业归属、标题、正文、状态、当前版本 |
| `report_section` | 标题层级、正文、锚点、结论状态 |
| `source` | 类型、URL/文件、标题、抓取时间、哈希、解析状态 |
| `source_chunk` | 文本片段、页码、位置、检索字段、嵌入可选 |
| `citation` | 报告段落、来源片段、引用说明 |
| `entity` | 企业、产品、行业、竞品、政策、概念等实体 |
| `relation_edge` | 起点、终点、关系、来源、置信度、确认状态 |
| `revision` | 报告快照、Diff、操作者、时间、AI 建议来源 |
| `research_job` | 导入、解析、搜索与 Agent 任务状态、错误、重试次数 |

## 7. 文档与联网处理

```text
URL / PDF / 图片 / 粘贴文本
  -> 类型、大小、页数、URL 安全校验
  -> 原文快照或文件卷保存
  -> 原生文本提取或页面图片渲染
  -> 多模态模型解析（按需）
  -> source_chunk + 页码/位置/哈希
  -> 全文索引 + 可选 embedding
  -> RAG / GraphRAG-lite
```

- 文字 PDF 优先使用原生文本提取，速度快且引用页码准确；
- 扫描 PDF 与图片使用视觉模型；初版不安装独立 OCR；
- 模型或搜索 Provider 未配置、超时或失败时明确展示失败状态；
- URL 仅允许 `http/https`，拒绝内网地址、文件协议和重定向到私有地址；
- 搜索分为 `domestic` 与 `global` 两个 Provider；跨境问题可并行搜索，但结果必须按来源范围展示，不能混成单一事实排序。初版优先使用 DeepSeek 原生 `web_search`，博查国内搜索保持禁用；DeepSeek 只能作为 `global_or_unknown` 来源，不能代替显式的国内搜索 Provider。
- 搜索结果与网页正文均是外部不可信输入，不能触发工具或写入操作。

## 8. 部署方案

```text
Internet
  -> Caddy/Nginx (HTTPS + 单账号保护)
  -> Next.js Web/API
  -> PostgreSQL
  -> 文件卷或 MinIO
  -> Search Provider (Tavily / Brave / SearXNG)
  -> OpenAI-compatible Model Provider
```

### 8.1 初版技术栈

- Next.js、React、TypeScript；
- PostgreSQL：报告、来源、引用、关系、版本与任务；
- PostgreSQL FTS：基础全文检索；`pgvector` 仅在语义检索确有不足时启用；
- 本地 GPU 可选 BGE-M3 Embedding Worker：云服务器只保存向量和执行检索，不加载模型权重；
- Docker Compose：单服务器部署；
- Caddy 或 Nginx：HTTPS 与单账号访问保护；
- 单个模型 Provider 与单个搜索 Provider：通过环境变量配置。

### 8.2 暂缓组件

LangGraph 仅在 V2 的受控研究 Agent 出现多步检索、暂停确认和可恢复任务时启用。Redis、RabbitMQ、Temporal、Kubernetes、Neo4j 和本地 GPU 模型均不属于初版依赖。

### 8.3 资源建议

- 当前目标服务器：2 vCPU、2 GB 内存、20 GB SSD、100 Mbps 峰值带宽；仅运行轻量 Web/API 与 PostgreSQL，不在服务器本地构建大镜像或运行本地模型；
- 外部模型/搜索 Provider：2 vCPU、4 GB 内存、50 GB SSD 是更舒适的个人版规格；
- 文件较多或需要并发解析：4 vCPU、8 GB 内存、100 GB SSD；
- 不在个人版服务器上直接部署大模型，除非另有 GPU 与隐私需求。

## 9. 完成标准

个人用户能够在服务器上完成以下闭环：

```text
创建慧策企业档案
  -> 导入官网、十五五规划 PDF 和竞品网页
  -> 搜索“免费跨境 ERP 的竞争压力”
  -> AI 返回有引用的解释
  -> 选中结论要求补充或改写
  -> 查看 Diff 并确认保存新版本
  -> 以 Markdown/PDF 导出调研报告
```

如果某个环节缺少来源、发生冲突或模型未配置，系统必须明确显示边界，而不是编造结果。
